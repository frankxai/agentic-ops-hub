# Post Voice Guide: FrankX / AI-Architect / Builder Education

## Core Pattern

```text
1. Name the mistake or shift.
2. Give the mechanism.
3. Show the operating model.
4. State the approval or safety boundary.
5. Give a specific CTA.
```

## FrankX Register

Use this for founder-facing posts.

Style:

- direct
- useful
- compact
- commercially literate
- opinionated but not inflated

Example shape:

```text
Most founders do not need more AI tools.

They need an operating system that tells every tool where it belongs.

The useful pattern:

- spaces for intake
- workspaces for execution
- source control for truth
- checks for proof
- approval gates for irreversible moves

Agents can prepare the work.

Humans approve the moves that create public, financial, production, or customer
risk.
```

## AI-Architect Register

Use this for enterprise/governance/professional posts.

Style:

- calm
- rigorous
- source-backed
- risk-aware
- implementation-oriented

Example shape:

```text
Enterprise AI adoption does not fail only because models are weak.

It fails when ownership, usage visibility, spend controls, and approval gates
arrive after deployment.

The operating model should define:

- who can delegate work
- where proof is recorded
- what gets measured
- which actions require approval
- how exceptions are reviewed
```

## Builder Education Register

Use this for tutorials and setup guides.

Style:

- practical
- step-by-step
- low jargon
- copyable
- proof-oriented


## Hook Bank

- Stop prompting agents like interns. Give them an operating system.
- Your AI stack does not need more tools. It needs lanes.
- The first agent workflow to design is the approval workflow.
- A coding agent without proof is just a confident black box.
- Slack is not the strategy. It is one way to make the strategy visible.
- The real stack is intake, workspace, truth, proof, approval, learning.

## CTA Bank

- Save this as your first agent ops checklist.
- Comment `agent OS` if you want the setup template.
- Use this before your next Codex or Claude Code session.
- Turn this into a one-page rule for your team.
- Start with the approval gate, then add autonomy.

## Avoid

- "unlock potential"
- "revolutionize your workflow"
- "10x everything"
- unsupported model rankings
- vague references to "AI agents" when the workflow is tool-specific
- implying public content is approved before `#social-approvals` says so

## Claim Rules

- If it is current AI lab news, cite official sources.
- If it is Frank's operating opinion, frame it as method or current answer.
- If it is a platform-performance claim, include source or label as hypothesis.
- If it touches enterprise, spend, governance, legal, health, or safety, use
  more cautious language.
