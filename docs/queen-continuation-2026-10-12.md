### What the component actually supplies

- Native exact thread/turn identity, metadata-only resume, steering/interruption and bounded history reads. Transport uses initialization, request IDs, an allowlist, bounded frames, deadlines and backpressure; unexpected server approval/tool requests are refused.
- Pinned controller/worker/verifier/transport source and effective permissions. Writable work requires an assigned isolated checkout and protected ownership proof before native access. Approval routing is checked on resume and each turn.
- Host-owned session leases across the native server and thread, including late callbacks. Immutable launch/turn receipts retain uncertain submissions. Lost acknowledgements cannot trigger blind replay. A digest-bound known-not-submitted marker is permitted only when the native call was synchronously never made.
- Canonical process-fence batches, immutable output capture before writable/unknown prior runs can be reused, and a safe native-retirement proof before detach. Missing host proof retains ownership or holds execution.
- Explicit finite bounds: 128 retained distinct nonces, 256 inspected native turns, 8,192-byte fence proof, 1 MiB inbound frames and bounded pending requests. These support a finite pilot; indefinite operation and large capture batches need further engineering.

These interfaces require a protected host that really enforces them. A receipt-shaped object, loaded policy or successful fixture cannot authenticate a caller, isolate Git, contain a process or enforce a continuous budget.
