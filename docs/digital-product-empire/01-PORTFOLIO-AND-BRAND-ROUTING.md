# 01 — Portfolio and brand routing

## One company, several clear doors

| Brand / surface | Who enters | Primary promise | Sell | Do not turn it into |
|---|---|---|---|---|
| **FrankX** | ambitious creators / AI architects | practical authority + premium outcomes | guides, paid kits, selective implementation | a generic tool directory |
| **GenCreator** | creators who want repeatable AI workflows | create/publish/grow with a coherent system | membership, creator kits, cohorts, studio workflow | enterprise consulting site |
| **Starlight Intelligence** | operators, teams, partners | governed intelligence systems | vertical AaaS, implementation, enterprise license | consumer creator school |
| **DPI** | sovereign wealth-minded creators | decide which owned income asset to build | diagnosis, relevant kits, eventually portfolio tools | funnel-first passive-income hype |
| **Arcanea** | culture / imagination audience | distinct IP and experiences | separate media, collectible, apps | professional B2B collateral |
| **Agentic Income** | buyers comparing agent tool choices | honest decision support | disclosed affiliate + specific starter kit | duplicate FrankX/GenCreator content |

### Routing rule

A visitor chooses an **outcome first**, then receives the appropriate brand and offer. Do not send everyone through the same newsletter, jargon, or checkout.

```text
Creator wants a repeatable content/product system → GenCreator
Founder needs an AI-native business workflow → FrankX → Starlight implementation
Team needs a governed vertical agent system → Starlight Intelligence
Creator needs income-asset choice support → DPI
Tool researcher → Agentic Income → relevant owned kit
```

## Product classes

### A. Free proof assets — acquisition

Open source, diagnostics, scorecards, mini templates, reference architecture, useful calculators.

**Purpose:** show quality and diagnose the next purchase.  
**Examples already aligned with estate:** ACOS/SIS open core, DPI gates, Agentic Income template, App Factory excerpts.  
**Never:** gated-for-email generic PDFs.

### B. Outcome Kits — self-serve paid digital product

An outcome kit contains an implementation-ready repo or starter, instructions, branded design contract, workflow/skills, test scripts, demo data, license, update promise, and a 30–60 minute first success.

**Initial kit families:**

1. **Agentic Business Starter** — a narrow workflow, not a blank SaaS boilerplate.
2. **Creator Product Launch Kit** — content/product journey and fulfilment system.
3. **Vertical Intake-to-Outcome Kit** — niche intake, review, artifacts, status and audit trail.
4. **App Factory Kit** — only after delivery proof; templates + QA + store release lane.

### C. Guided installs — productized service

Fixed scope, fixed timebox, template-backed, human approval gates.

```text
Discovery / diagnosis → configured kit → branded deployment → staff handoff → 30-day outcome review
```

This is the fastest legitimate cash path and produces the evidence to make the kit better.

### D. Vertical SaaS / AaaS — recurring revenue

One repeatable job with the same domain model, onboarding, permissions and metrics across customers. Tenant customization must be config/brand/connector level, not forked code.

### E. Partner / enterprise licensing

License a verified vertical system, deployment playbook, training, support SLA and governed swarm operation. It is not a raw model token resale scheme.

## The "one core, many faces" architecture

```text
Shared core:
SIS identity/memory policy · App Factory · design tokens · auth/billing adapters
policy gateway · audit receipts · evals · optional MCP tools

Product modules:
vertical schema · branded UI · approved connectors · prompts/skills · reporting

Tenant config:
brand tokens · roles · connectors · pricing/metering · workflows
```

**Fork only when:** regulation, data boundary, core ontology, or brand/IP requires it.  
**Otherwise:** keep a module and tenant config.

## What not to build now

- A broad "build any app with AI" platform: competes directly with funded general builders and loses differentiation.
- A public marketplace of hundreds of unvalidated agent skills.
- Separate near-identical sites for every niche.
- A fully autonomous agent with money/publishing/admin rights.
- A custom app agency disguised as product revenue.
