# Starlight Social Media Team OS

Created: 2026-06-26

Status: internal operating system. Nothing in this document approves external
publishing, scheduling, customer messages, spend, deploys, merges, Slack access
changes, or Hermes gateway activation.

## Purpose

Build a guarded, high-taste social production system for FrankX, AI-Architect,
Builder Education, GenCreator, Tooling, and selected Starlight portfolio lanes.

The system turns signals into durable assets:

```text
Signal -> brief -> deterministic asset -> QA -> Slack proof -> approval packet
  -> human decision -> manual publish/schedule -> performance learning
```

The team optimizes for founder-useful proof, not content volume.

## Approval Gates

Agents may research, draft, generate internal artifacts, inspect outputs, run
local checks, summarize, create approval packets, and post internal proof.

Human approval is required before:

- publishing or scheduling social posts
- sending customer or partner messages
- deploying or promoting production
- merging to main
- spending money or activating vendors
- changing access, channel membership, DNS, or domains
- starting Hermes gateways or autonomous profile runtimes

Approval language must request one of:

- `APPROVE`
- `APPROVE WITH EDITS: <edit>`
- `REVISE: <reason>`
- `HOLD`

## Cadence

Daily:

1. Read new signals from AI labs, platform changes, Slack approvals, repo proof,
   design QA, and prior performance.
2. Pick at most one carousel candidate unless there is a major update.
3. Build or revise one durable asset pack.
4. Post concise proof to `#social-carousels`.
5. Route approval-ready candidates to `#social-approvals`.
6. If there is no meaningful output, do not manufacture noise.

Weekly:

1. Review approved, rejected, revised, held, and ignored packets.
2. Review performance if posts were manually published.
3. Promote the best pack into a reusable client/community template.
4. Cut stale lanes, duplicated variants, and weak platform assumptions.
5. Update brand guides when Frank's approvals reveal a pattern.

## What Belongs Where

### Slack

Slack is the visible cockpit: routing, proof, approvals, decisions, short
updates, and learning summaries. It is not the canonical long-term asset store.

Use Slack for:

- concise proof updates
- approval requests
- final decision receipts
- design QA findings that should become reusable
- performance learning summaries

### Repo

The repo is durable truth.

Use the repo for:

- briefs
- source links
- deterministic deck source
- approval packets
- evidence and QA notes
- reusable brand/lane foundations
- learning ledgers and automation registry

### Canva

Use Canva when:

- a human needs easy editing after the deterministic source exists
- a campaign needs many manually adjusted variants
- brand kits, social scheduling handoff, or team review in a familiar tool matter
- the artifact is more marketing package than code-native system

Do not use Canva as the only source of truth for exact technical diagrams,
claim tracking, or automation-readable evidence.

### Local HTML/SVG/PDF

Use local deterministic production when:

- exact text, slide numbers, diagrams, or channel names matter
- the output should be reproducible and diffable
- the deck needs PDF export for LinkedIn
- the pack should become a client/community template

### Generated Image Assets

Use image generation for:

- cinematic covers
- visual metaphors
- thumbnails
- mood frames
- campaign art
- non-text-heavy scene concepts

Do not use generated images for final exact slide text, final diagrams, product
UI claims, logos, source citations, or dense labels.

The local imagegen skill says the built-in `image_gen` tool is the default for
normal raster generation. CLI/model-specific behavior must be checked in the
current local skill and official docs before relying on it. The Social Media
Team OS should not depend on a specific model name such as GPT Image 2; it
depends on the method: brief, generate, inspect, critique, iterate, approve.

## Image Generation + HTML/Canva Workflow

1. Write the outcome contract: audience, surface, first read, proof, failure
   modes, and acceptance gate.
2. Decide production method:
   - exact text/data/UI/diagram: deterministic HTML/SVG/Figma/Canva
   - cinematic cover or metaphor: generated image plus inspection
   - editable campaign family: deterministic source first, Canva variant second
3. For generated images, write a short art direction prompt with final crop,
   brand tokens, subject, composition, and avoid list.
4. Inspect the actual output. Reject fake text, fake logos, malformed UI,
   private data, weak crop, artifacts, or generic prompt style.
5. Add exact overlay text outside the generator when needed.
6. Export final assets and record paths, prompt, QA score, and approval gate.

## Learning Loop

The daily carousel factory must learn before producing:

- AI lab updates from official sources only when topical claims are made
- prior approval decisions from `#social-approvals`
- prior design QA scores from `#design-intelligence` and pack `evidence.json`
- prior performance when manually published posts have metrics
- brand-specific guides in `starlight-design-intelligence` and this docs tree
- Frank's direct edits, especially headline, stack, tone, and claim-risk edits
