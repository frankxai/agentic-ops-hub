## ChatGPT plans and the SDK decisions

Eligible Plus and Pro users can separately consent to plan-backed requests in participating applications. Commercial website sign-in remains selected-partner access. Identity, Starlight membership, connector authorization and model usage permission are separate boundaries. There is no access to the person's ChatGPT conversations through these scopes. [OpenAI quickstart](https://developers.openai.com/siwc/quickstart).

The supported route discovers account models and calls public Responses with `store:false`, `stream:true` and explicit context. The current Starlight worker handles text only. The provider supports more inputs/local tool patterns than this worker implements, but does not support hosted MCP, image generation, Code Interpreter or native computer use through this route. `max_output_tokens`, background and HTTP previous-response continuation are also unsupported. Keep capability tables per route. [Models and inference](https://developers.openai.com/siwc/token-sharing-open-source/models-and-inference), [preview limitations](https://developers.openai.com/siwc/token-sharing-open-source/preview-limitations).

Each person uses their own authorized account. Plan usage/token pooling, limit evasion and one subscription fulfilling another user's requests are prohibited. A Starlight service fee must account for the application's own value and eligibility; it cannot promise resale of ChatGPT quota. [SIWC terms](https://openai.com/policies/sign-in-with-chatgpt-terms/). The inspected official DevKit at `0a36fef` has a noncommercial license; this worker copied no source and added no DevKit dependency. Separate product eligibility/terms still apply. [Pinned license](https://github.com/openai/sign-in-with-chatgpt-devkit/blob/0a36fefeb913055c8c7a1a29b63d82b96b2e841a/LICENSE).

## The user experience worth proving

Reuse accepted Canvas, Command, Observatory, SIS and GenCreator journeys. Avoid another dashboard product. A user states a useful goal, supplies permitted sources, sees a proposed scope/model/team/budget, admits the task and receives editable work with evidence and a recovery record. Desktop adds OS credentials/local files; CLI adds scriptability and repeatable export; web adds accessible review and managed continuity; ChatGPT adds a familiar tool/UI entry point.

Start with the already selected technical-founder job: one issue-bound investigation produces a checked repair artifact. In parallel at the programme level, preserve the requested creator journey: one permitted source becomes an editable, source-bound draft with revisions. Delivery can be sequential on this machine. Coding dispatch follows actual isolation proof. A full book, campaign or website requires its own acceptance, not a template preview.

Proposed profile examples:

| Profile | Depth and artifact |
| --- | --- |
| Software/product | Brief challenge, architecture, implementation, accessibility/security review, preview and recovery record. |
| Content/research | Source verification, argument, voice editing, cited draft and channel adaptations; publication separately authorized. |
| Books | Structure, research/world/canon where relevant, character development, developmental/line editing, continuity and publishable manuscript sections. |
| Operations | Source-bound diagnosis, repair proposal, bounded change, reliability proof and rollback. |
| Learning/Genius | Candidate discoveries, falsifiable experiments, counterexamples and evaluated improvements. |

Each profile needs input/output contracts, named accountable lead, permissible tools, minimum recall, budget, cancellation and acceptance. Keep many specialties discoverable; activate only the independent work needed. Current resource admission reported 27 Codex task runtimes and approximately 1.3 GB free RAM, below the 4 GB floor. No new workers or heavy jobs were launched.

## Memory, learning, dreaming and self-healing

Proposed memory policy:

| Scope | Store/recall | Promotion rule |
| --- | --- | --- |
| Queen | Authoritative goals, owner/grant pointers, decisions, acceptance and cost state | Source-backed records with explicit dates; never treat a worker claim as final truth. |
| General/team | Domain procedures, standards, dependencies and lessons | Evaluate before cross-team promotion. |
| Worker/task | Necessary task context, local findings and evidence | Return an artifact and a compact proposed lesson; no unrestricted tenant recall. |
| Genius/research | Hypotheses, experiments, rejected alternatives and contradictory findings | Keep speculative findings separate from accepted procedures. |
| User/tenant | Consented preferences, project records and retention settings | Scope reads/writes to the user; prove export/deletion and revoke access. |
| Shared operational memory | Approved reusable knowledge and protocol | Preserve Markdown/provenance as source and rebuild indexes. |

Hermes' upstream learning mechanisms are useful: learn a repeatable procedure from a real task, improve skills after corrections and keep small durable facts. Upstream dreaming is also available as a community plugin. These descriptions do not prove estate activation or learned model weights. Preserve current SIS authority and existing local memory providers. [Hermes skills](https://hermes-agent.nousresearch.com/docs/user-guide/features/skills/), [memory](https://hermes-agent.nousresearch.com/docs/user-guide/features/memory), [dreaming plugin](https://hermes-agent.nousresearch.com/docs/plugins/hermes-dreaming).

Learning should follow: outcome/feedback → source-linked candidate → evaluation against incumbent → independent review where consequential → versioned promotion → continued monitoring and rollback. Healing must diagnose actual failures, apply bounded authorized repairs and preserve uncertain execution. Dreaming should consolidate, deduplicate and flag contradictions while retaining original evidence.

For the 10,000-repository ambition, first build a lightweight pinned metadata/license manifest. Study a small relevant subset, initially around 20 repositories, for the current engineering problem; hydrate more only when admitted and useful. Repository text is untrusted input. Do not auto-install skills/hooks, run imported code, bulk-clone the corpus or equate stars with quality. Measure accepted improvements, their maintenance cost and regressions. A fully populated corpus and evaluated promotion system remain future work.

Illustration, not a benchmark: 100,000 uncached short-context input tokens and 10,000 output tokens cost approximately $0.015 on Luna, $0.30 on Sol or $1.50 on Astra. Eight identical Sol calls cost $2.40 before tools/infrastructure. Model suitability must be measured; no assumption of equal quality follows from these prices.

A ten-minute sandbox with four GB provisioned memory and two billed active-CPU minutes costs about $0.0184 for those two dimensions. One thousand such jobs cost about $18.40, plus creations and other charges. At 600 workflow events per job, one thousand jobs add about $12 in workflow event charges, plus data/Queues/Functions. These workload quantities are assumptions; included credits and actual regional billing can change the invoice.

The unit economics ledger should include every lead/worker/reviewer call, cached and uncached tokens, tool charges, retries, failures, compaction, retained state, infrastructure and human repair. Measure cost per accepted artifact. Plan-backed usage still has quota and opportunity cost; it is not unlimited free capacity. Reserve conservatively where exact token ceilings are unsupported and retain unknown costs until reconciliation.

Illustrative ROI: 40 accepted tasks/month saving 30 net minutes each recover 20 hours. At an assumed $75/hour value, that is $1,500/month. At an assumed $100/month operating cost, operating ROI is 1,400% and operating break-even is 80 minutes saved. If building/maintaining the initial product also costs an assumed 200 hours at $75/hour, the $15,000 upfront investment takes about 10.7 months to recover at that benefit. First-year ROI including that build cost is about 11%. These are scenario inputs, not measured Queen returns, income or delivery estimates.

Run a two-week pilot against the same native Codex/manual workflow. Record accepted artifact quality, elapsed and active time, founder review minutes, repairs, all-in cost, restart success, duplicate external actions and repeated use. Pilot targets should include zero duplicate unauthorized actions and explainable budget accounting; set quality/time acceptance with the real user. Validate willingness to pay and support burden before choosing service pricing. Users may value continuity, dependable artifacts and control more than an agent roster.
