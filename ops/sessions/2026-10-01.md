Frank asked whether Grok's startup changes preserve agent capability and what setup to keep. This slice audited the live machine and existing source; it did not change startup settings, wrappers, tasks, binaries, or harness configuration. The implementation remains open under [starlight-agent-config issue 46](https://github.com/frankxai/starlight-agent-config/issues/46), which already requires reconciling the existing optimization owner's lane.

Verified:

- The delayed Startup VBS calls `Start-DelayedMemoryGateway.ps1`. That script waits 180 seconds, checks for the built SIS gateway and Node, skips an occupied port 5200, and starts the built daemon without compiling. A future sign-in and its elapsed startup time were not tested.
- Agent memory reads work through the authenticated shared tool plane on loopback port 7317. Actual `memory_stats` and `memory_search` calls succeeded. Stats reported 297 atoms and 297 vectors. The plane status still says `degraded`; successful memory calls do not prove all backends healthy.
- Port 5200 is a separate SIS gateway. Ports 7318, 4200, 4321, and 3111 were closed in the sample. The plane's original boot/logon task is disabled, while its recovery watchdog remains enabled. Its recent log records successful HTTP probes, not merely an open port.
- Codex and Claude configuration point shared reads at 7317. Both native memory definitions use `--profile writes`; the Codex native definition is disabled. Shared reads do not grant saving new memory. Other harnesses and cloud ChatGPT were not tested.
- The tray source polls every 30 seconds, checks 5200 and 4200, and launches PowerShell for Fleet Supervisor task state on the UI thread. `ReadToEnd()` occurs before its `WaitForExit(3000)`, so that call does not bound the preceding blocking read. The source's exact correspondence to the running EXE was not rebuilt or verified.
- `StarlightCrossRepoIndexer` imports Claude project memory through `python -m indexer --all`. It is not a repository code-search index and would not replace the broad ripgrep walks reported by Frank.
- The Bash ripgrep wrapper prepends exclusions before caller arguments. Later glob arguments can override earlier exclusions, as documented in [ripgrep's guide](https://github.com/BurntSushi/ripgrep/blob/master/GUIDE.md). Neither inspected wrapper rejects broad estate roots or deduplicates concurrent requests. PowerShell/direct binaries can also bypass those wrappers.
- Machine admission allowed one interactive workload, retained the 4 GiB floor, and held new swarms. Storage admission reused the recent quick sensor plus a fresh drive reading; only a small sparse handover checkout was added. No builds, installs, models, indexers, or new resident services ran.
- The legacy scheduled secret scan and substrate backup tasks are disabled. Their current replacements and latest successful backup were not verified; this is an unresolved ownership/recovery check, not evidence that no security checks or backups exist.
- Several indexed guide paths, including capability-loading and PP/search-safety skill paths, were absent in the checked primary branch; capability-loading was also absent in that checkout's existing `origin/main` ref. Do not treat a catalog entry as proof its target is installed.

Recommended setup:

1. Keep the tray and essential user applications at sign-in. Keep the current delayed, prebuilt-only 5200 launcher pending a real sign-in check. There is no benefit demonstrated here from making memory start in the first minute.
2. Give local agents a single shared read endpoint on 7317, load its memory backend on use, and retain bounded direct vault reads when unavailable. Keep writes explicit through the existing task-scoped profile. Preserve on-demand Canvas, SIS, Substrate, dashboards, and gbrain.
3. Fix search admission first: route via the existing repo registry and skill index, require named repositories/files, reject recursive home/drive/estate-root targets, apply mandatory exclusions after user options, cap threads, and serialize/deduplicate broad searches. Use bounded timeouts and cancel only the caller's search. Validate direct-binary and shell bypass limits rather than claiming universal enforcement.
4. Keep lifecycle ownership in one existing launcher/watchdog. A native delayed logon trigger can replace the sleeping PowerShell later if measured startup overhead warrants it. The tray should display both services, cache supervisor state for several minutes, refresh on menu open, and perform bounded probes away from the UI thread. Moving lifecycle ownership into the tray has no measured benefit from this audit.
5. Reuse the existing registry before proposing a code-search index. If searches still justify one, implement a scoped incremental index in the existing owner lane with an idle/AC-only bounded job. Do not enable the Claude memory importer as a substitute. [Windows supports idle conditions](https://learn.microsoft.com/en-us/windows/win32/taskschd/task-idle-conditions) and [native logon delay](https://learn.microsoft.com/en-us/windows/win32/taskschd/logontrigger-delay).
6. Verify the currently authoritative backup/security jobs independently of startup trimming. Do not disable protections to improve login time. Keep Dreaming disabled.
