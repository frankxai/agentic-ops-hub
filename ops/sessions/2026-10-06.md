## agentic-jujutsu research and a build plan for our own agent version control (Claude)

Frank asked what `agentic-jujutsu` is, what it needs, whether to use it, and how to build something better. Nothing was installed or run. Sources: npm metadata, the 2.3.6 tarball README (downloaded with `npm pack`, not installed), `gh` repo stats.

### What it is

- Package `agentic-jujutsu` 2.3.6, MIT (`LICENSE`, Copyright 2025 Agentic Flow Team), author ruvnet (ruv@ruv.net).
- Lives in `ruvnet/agentic-flow` under `packages/agentic-jujutsu` (815 stars, 178 forks, last push 2026-09-16, GitHub reports no licence on the repo itself).
- Separate from ruflo (`ruvnet/ruflo`, the renamed claude-flow, 73,929 stars). A code search finds 8 files in ruflo that mention it; not read.
- Rust N-API addon with the `jj` engine embedded (Linux build 27 MB; README still says 8 MB). Windows binary is the optional dependency `agentic-jujutsu-win32-x64-msvc`. One runtime dependency, `@qudag/napi-core`.
- AgentDB is not a dependency. `agentdb` is a separate ruvnet package (3.0.0-alpha.20); the wrapper has built-in operation tracking that the README calls AgentDB.
- Last publish 2025-11-24. 14 of 15 versions landed in two weeks.

### Layers

1. Jujutsu (`jj`, Martin von Zweigbergen, Google): no staging area, working copy is a commit, conflicts stored as data, operation log with undo, workspaces sharing one store, Git-compatible.
2. Wrapper: `JjWrapper` for Node, MCP tools, CLI.
3. Intelligence layer: ReasoningBank (task, operations, score, critique), `getSuggestion` by similarity, operation tracking, QuantumDAG coordination.

### Verdict: skip the package, absorb the patterns

- The README's v2.3.4 notice says ML-DSA signatures, SHA3-512 fingerprints and HQC-128 encryption are placeholders, real crypto promised for 2.4.0. 2.4.0 was never published. The `/agentic-jujutsu` skill text presents these as working. They are not.
- The 23x speed and 87% conflict-resolution figures are the author's own, with no independent benchmark. The 23x is against Git index locks, which one-branch-per-agent already avoids.
- Learning needs 5 to 10 scored runs and the scores are self-graded.
- RAM was not measured. No figure in the README. A Node process plus a Rust addon is expected in the tens of MB. The real cost is the number of agents run in parallel.
- Overlaps `starlight-memory` (Retrieval v2, eval) and Langfuse.

### Build plan: our own, better

Working name: `agent-trails` (not created; pick the name and the repo home before building). Principle: depend on the `jj` CLI, do not fork the wrapper. Fork only if a trial shows the napi binding earns its 27 MB.

| Layer | What | Beats upstream by |
| :--- | :--- | :--- |
| 0 | Plain `jj` colocated with Git in each product repo | Mature, maintained engine instead of a wrapper around it |
| 1 | `agent-workspaces`: `jj workspace add` per agent, bookmark `agent/<harness>/<scope>`, refuses in CRITICAL/TIGHT storage mode, one writer per workspace | Disk cost lower than Git worktrees; honours the storage contract and the parallel-agent protocol |
| 2 | Op-log receipts: `jj op log` plus diff stat exported per session, signed with Git or SSH signing, fed to `pr-gate` as maker evidence | Real signatures, not placeholders; checker differs from maker |
| 3 | Trajectory record type in `starlight-memory`: task, steps, outcome, critique, grader identity (never the maker) | One memory system, graded by a different provider, retrievable with the existing Retrieval v2 |
| 4 | Arcanea canon pilot: parallel lore edits kept as conflict objects for `canon-guardian` | Speculative. Needs its own design pass against `CANON_LOCKED.md` |

Exit gates, each proven in a sandbox in both directions (see memory: gates must be tested):

- G1: three agents commit concurrently in three workspaces on a scratch repo; no lock errors; `git push` to a throwaway remote round-trips. Record RAM and disk against three Git worktrees.
- G2: a receipt verifies, and a tampered receipt fails.
- G3: with trajectory suggestions on versus off, the same ten tasks, graded by a different provider. Ship layer 3 only if suggestions measurably help. Upstream never ran this comparison.

### Collab and reuse

- Reuse: the package is MIT, so copying and modifying is allowed with the notice kept. The `agentic-flow` repo shows no licence on GitHub; confirm the licence of any file taken from there before copying. Ruflo's licence was not checked.
- Collab: open an issue upstream offering the placeholder-crypto removal and a Windows CI result. Do not depend on a reply.
- Alternatives if `jj` disappoints: GitButler, Sapling, Pijul. Not evaluated here.
