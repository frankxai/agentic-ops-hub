## Memory, context and agent responsibility audit

Owner: Codex, isolated branch `agent/codex/memory-architecture-20261016` from
reviewed hub main `4e4afabcec80f9e4dc5a51e396b9808ba4938db9`.
Scope: research, bounded inspection and proposed delivery order. No implementation
or runtime rollout is claimed. Private source contents and machine evidence remain
outside this public repository.

Issue updates: [SIS49 recovery and conformance](https://github.com/frankxai/Starlight-Intelligence-System/issues/49#issuecomment-6223272646)
and [memory2 adapter conformance](https://github.com/frankxai/starlight-memory/issues/2#issuecomment-6223271756).

Frank requested an assessment of context and memory across local/cloud harnesses,
swarm/individual responsibilities, Starlight's role, existing engineering and
external memory alternatives. The useful acceptance target is a source-cited task
continuation with preserved constraints, authority, ownership and recovery.

Findings:

- The shared memory backend was unavailable during inspection. A bounded local
  startup reproduced a vault-file admission failure. The source-owner recovery
  must preserve the source ledger and file bounds; writer-side admission and
  useful backend failure reporting should prevent recurrence.
- SIS context-continuity PRs [345](https://github.com/frankxai/Starlight-Intelligence-System/pull/345),
  [354](https://github.com/frankxai/Starlight-Intelligence-System/pull/354) and
  [355](https://github.com/frankxai/Starlight-Intelligence-System/pull/355) were
  verified merged. Older pending receipts remain historical evidence.
- Provider lifecycle/conformance, current host capability receipts, cloud account
  acceptance and an end-to-end paired comparison remain open. A documented
  adapter, historical passing test or merged PR does not certify current service.

Proposed responsibility boundaries: Registry owns reviewed portfolio identity and
architecture; SIS owns intelligence/provenance contracts; memory owns scoped
record/retrieval/lifecycle implementation; source owners retain their records;
agent-config owns harness projections; existing Queen/runtime owners govern
admission and durable jobs. A native task lead owns integration, workers own
explicit paths/artifacts, and an independent reviewer judges the exact revision.
Model selection and harness selection are separate from role identity.

Retain the local canonical sources and existing hybrid baseline. Compare Hindsight
and Graphiti for a named advanced-recall job, with Caura as a Postgres challenger.
Choose a document pipeline only for a specific corpus. Personalization remains a
separately scoped experiment. All are proposals pending evaluation.

The alternatives research used current primary sources. Current Graphiti upstream
distinguishes Zep's proprietary Context Graph Engine; Mem0 Platform documents
native graph memory; MemoryGraph currently defaults to FalkorDBLite with SQLite
as a fallback; Hindsight is MIT. The supplied vendor comparisons do not establish
a winner on Starlight's workload.
