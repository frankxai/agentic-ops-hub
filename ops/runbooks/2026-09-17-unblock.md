## 1. Fix the deadlocked pipeline  (HIGHEST VALUE — unblocks 4+ PRs)

**Problem:** `agentic-ops-hub` uses *classic* branch protection with
`required_approving_review_count: 1`. Every PR is authored by `frankxai`, the only
collaborator, and GitHub forbids self-approval. The rule is **unsatisfiable** — PRs

deletion, block force-push, gate on checks). They merge fine. This makes the third
repo match them — it is a normalization, not a weakening.

### Do it yourself (UI, ~30s)
GitHub -> `frankxai/agentic-ops-hub` -> Settings -> Branches -> `main` rule ->
uncheck **Require a pull request before merging** (or set approvals to 0) -> Save.

## 3. Stale branches — delete 23, NOT 236

The original audit said "delete 236". **That would have destroyed real work.**
Verified breakdown: 3 fully merged + 20 squash-merged = **23 safe**;
135 have a CLOSED (rejected) PR; **78 have no PR at all and hold 402 commits
that exist nowhere else.**

Exact safe list: `ops/audits/2026-09-15-estate/safe-to-delete-branches.tsv`
Full evidence: `branch-merge-status.tsv`, `branch-verdicts.tsv`

```bash
while IFS=$'\t' read -r repo br; do
  def=$(gh api "repos/frankxai/$repo" --jq .default_branch)
  ahead=$(gh api "repos/frankxai/$repo/compare/$def...$br" --jq .ahead_by)
  pr=$(gh pr list -R "frankxai/$repo" --head "$br" --state all --json state --jq '.[0].state')
  if [ "$ahead" = "0" ] || [ "$pr" = "MERGED" ]; then
    gh api -X DELETE "repos/frankxai/$repo/git/refs/heads/$br" && echo "deleted $repo::$br"
  else
    echo "GUARDED $repo::$br"
  fi
done < ops/audits/2026-09-15-estate/safe-to-delete-branches.tsv
```
The guard re-verifies each branch at delete time; it cannot delete unmerged work.

### 2026-09-19 (cont.) — what restored CI then exposed

Fixing CI did not create failures; it made six months of hidden ones reportable.

**Adapter design conflict — filed as `arcanea-platform` issue #36, deliberately NOT "fixed".**
`packages/aios/tests/aios.test.mjs` is byte-identical across both repos (blob `6a87cd10c0`)
and demands `execute()` reject with `AdapterNotImplementedError`. But the two repos' sources
have genuinely diverged:

| | `arcanea` (4,099 b) | `arcanea-platform` (3,507 b) |
|---|---|---|
| `AdapterNotImplementedError` | defined, all 4 adapters throw it | **class does not exist** |
| `execute()` | `throw new AdapterNotImplementedError(this.type)` | returns `` `[Claude] Processing: ...` `` |
| `isAvailable()` | simplified | real checks: `!!process.env.GEMINI_API_KEY`, `!!process.env.OPENAI_API_KEY` |

Porting the twin's file would DELETE working behaviour (env-key checks, populated adapter
registry) purely to turn a test green. That is a product decision, not CI cleanup, so it was
escalated rather than silently chosen. **Rule: never overwrite a working implementation to
satisfy a test without deciding which design is intended.**

**TypeScript debt in `apps/web` — 71 errors, two root causes found, 33 fixed (PR #37):**
- **TS2339 x29, all one line.** `listing-page.tsx:298` used
  `ListingPageProps["items"] extends Array<infer U> ? U : never`, but `items?:` is optional so
  the type is `Array<...> | undefined`; a union does not extend `Array<infer U>`, collapsing the
  conditional to `never`. Fix: wrap in `NonNullable<>`.
- **TS2484 x4.** Four template files exported their props type twice — `export interface XProps`
  plus a tail `export type { XProps };`. Removed the redundant tail; public API unchanged.
- **TS2322 x35 left alone**: `Icons` is defined *inline per page*, not shared, so it is ~35
  scattered edits, not one fix. Bundling them would make the PR unreviewable.

Note the four template files **DIFFER** between the twins (all 4 blob SHAs differ), so this fix
applies to `arcanea-platform` only — more evidence the repos are drifting.
